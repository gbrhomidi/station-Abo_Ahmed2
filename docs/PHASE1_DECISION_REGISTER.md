# سجل قرارات المرحلة الأولى

هذا السجل هو بوابة اعتماد، وليس بديلاً عن اعتماد صاحب الصلاحية. لا يجوز للمهندس تحويل حالة أي قرار إلى `APPROVED` أو إدخال اسم/تاريخ اعتماد غير موثق. تغيير الحالة يتطلب توقيعاً أو مرجعاً خارجياً قابلاً للمراجعة، مع تسجيل الأثر والقرار البديل عند الرفض.

## حالات السجل

- `PENDING_OWNER_APPROVAL`: القرار مطلوب ولم يعتمد بعد.
- `APPROVED`: اعتمده صاحب الصلاحية مع مرجع وتاريخ.
- `REJECTED`: رُفض مع سبب وقرار بديل.
- `SUPERSEDED`: استبدل بقرار أحدث، مع رابط القرار البديل.

## قواعد حماية المرحلة

1. لا يوجد Backfill تاريخي تلقائي في تهيئة المخطط أو القراءة أو العامل أو جسر الواجهة.
2. لا تُعاد كتابة `due_date` أو الأرصدة التاريخية قبل اعتماد القرارات ذات الصلة وإنشاء dry-run وخطة رجوع ونسخة آمنة.
3. أي قرار مالي أو تجاري يخص تاريخ العمل، شروط الدفع، العملة، التقريب، أو الأرصدة يحتاج اعتماد صاحب النظام/المحاسب المسؤول، وليس موافقة المطور وحده.
4. كل اعتماد يجب أن يرفق: اسم المعتمد، الدور، التاريخ/الوقت، مرجع الموافقة، النص المعتمد، ونطاق الأثر.
